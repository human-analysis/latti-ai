# CryptoFace / Latti-AI variant registry

Last audited: 2026-07-25

This is the durable index of CryptoFace FHE variants, preserved results, and
investigative work areas under `/research/hal-vishnu/external`. Update it when a
variant is created, promoted, rejected, or superseded. The current security and
scheduling checklist is in
[`cryptoface_security_gpu_scheduling.md`](cryptoface_security_gpu_scheduling.md).

## How to read the results

- **Promoted** means the variant passed its stated numerical, repeatability,
  security, and latency gates. It does not mean every metric was collected
  under identical host contention.
- **Clean reproduction** means the folder has committed provenance, checksums,
  runtime, model, and validation evidence.
- **Experiment snapshot** means useful artifacts remain, but the folder is not
  immutable. The `sec128-*` folders are modified copies of commit `5cb6e12`;
  their copied baseline README/validation files do not prove that each
  folder-specific parameter change passed.
- Unless noted otherwise, accuracy is a 256-value embedding comparison against
  a frozen PyTorch or accepted encrypted-output oracle. Later gates require
  relative L2 <= 0.03, maximum absolute error <= 0.01, and all values finite.
- "Inference/image" is core encrypted inference. "Pair interval" is aggregate
  multi-GPU processing time divided by 128 pairs; it measures throughput, not
  the latency of two serial image requests.
- The embedded 128-pair subset has only positive pairs. Cosine values and
  embedding errors are valid, but it cannot establish balanced face
  verification classification accuracy.
- Security is accepted only when the complete relevant classical attack suite
  clears 128 bits. Earlier screening estimates that omitted sparse-secret
  hybrid attacks are labelled as such.

## Latency reporting contract

Every new performance variant must report two separate gates under recorded
hardware and contention conditions:

1. **Idle single-pair latency:** one GPU and one persistent worker processing
   two images. Report total pair processing wall time plus cold-image and
   hot-image runner-recorded encrypted inference separately. The hot image must
   reuse only the state explicitly allowed by the variant.
2. **Sustained throughput:** the fixed 128-pair/256-image workload, normally
   with one persistent worker on each of GPUs 1, 2, and 3. Report total
   processing time, aggregate pair interval, images/second, overall and hot
   per-image inference distributions, worker balance, utilization, and peak
   memory.

Single-pair latency and aggregate pair interval are never interchangeable.
For historical entries, a missing gate means **not measured**; do not infer it
from the other metric. A variant cannot be called a general latency improvement
until both gates pass accuracy, security, memory, and runtime-stability checks.
